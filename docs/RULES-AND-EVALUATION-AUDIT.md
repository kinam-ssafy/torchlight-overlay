# 블러드 러스트 규칙과 모델 검증 조건 감사

2026-11-04. 이 문서는 실험 조건과 확인 수준을 구분한다. 시뮬레이션의 통계적 유의성은
실제 게임 규칙의 정확성, 실전 보상 확률 또는 전역 최적성을 보증하지 않는다.

## 기존 4,096판 기준의 한계

독립 표본의 단위는 한 판이다. 같은 판에서 얻은 수십 개 상태, 선택지마다 계산한 수백 개
미래, GPU 학습 행 수를 독립 판수로 세면 안 된다. 기존 `release_quality`의 4,096판/256
미래는 최소 계산량 기준이며, 통계적 충분성 기준이 아니라고 코드에도 명시했다.

성공률을 추정하는 문제와 두 정책의 차이를 검출하는 문제는 다르다.
4,096판의 성공률이 50%이면 Wilson 95% 구간 반폭은 약 1.53%포인트다.
그러나 같은 시작 시드에서 두 정책의 성공/실패가 갈리는 비율 q가 40%라면:

| 실제 개선 폭 | 4,096판 검출 확률 | 8,192판 검출 확률 |
|---|---:|---:|
| 1%포인트 | 16.7% | 29.3% |
| 2%포인트 | 51.6% | 81.2% |
| 3%포인트 | 85.4% | 99.0% |

이는 유의수준 5%, 양측 exact McNemar 검정의 사전 검정력이다. q=25%이면
2%포인트 차이에 대한 검정력은 각각 71.6%, 95.0%다. 따라서 8,192판도 모든 모델,
모든 개선 폭에 충분하지 않다. 관측된 최종 결과로 검정력을 다시 정의하지 않는다.
`audit_sample_size.py`가 이산 이항분포를 합산해 위 수치를 재현한다.

같은 초기 시드는 유효한 대응 비교를 만들지만, 행동에 따라 난수 소비가 달라지므로
이후 카드까지 동일하다는 뜻은 아니다. 최종 비교에서는 대응 exact 검정과 대응 재표집
신뢰구간을 사용한다. 개별 모델의 Wilson 구간을 차이의 신뢰구간으로 오해하지 않는다.
유의하지 않은 결과는 동등성 또는 최적성의 증명이 아니다.

기존 native `gate`는 840k 달성 순증이 `max(5, ceil(N/100))` 이상이고 상한 평균 하락이
5,000점 이내이면 통과시키는 실용 규칙이다. 출력하는 우연 확률을 통과 조건에 직접 쓰지 않고,
입력의 겹치는 시드만 비교하므로 `pass=yes` 자체가 통계적 검증 완료를 뜻하지 않는다.
이번 평가기는 비어 있거나 중복/누락/서로 다른 시드를 거부하고, 고정 판수의 정확 대응 검정을
별도로 수행한다. native gate 출력은 호환용 진단으로만 함께 기록한다.

하위 10% 점수와 30만 미만 비율도 별도로 기록한다. 희귀 실패는 표본이 적어 오차가 크며,
하위 분위수가 숫자로 높아졌다는 것만으로 저점의 비열등성이 입증되지는 않는다.
매 선택의 256 futures 역시 작은 선택지 간 차이를 확정하기에 충분하다고 단정할 수 없다.
현재 탐색은 모든 대상 조합을 끝까지 계산하지 않는다. 각 카드의 즉시 점수가 가장 높은 대상과
상위 일부 조합을 먼저 고르고 그 후보들만 깊게 평가한다. 후보에서 빠진 장기 시너지 조합은
판수나 futures를 늘려도 복구되지 않는다. 따라서 이번 검증은 이 제한된 탐색 정책의 성적이며,
모든 합법적 행동을 포함한 전역 최적 정책의 증명이 아니다.

근거: [NIST Wilson 신뢰구간](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm),
[SciPy exact binomial test](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.binomtest.html).

## REA와 로컬 파일 조사 결과

[REA](https://github.com/morluto/rea) 6.8.0을 작업 폴더에 설치해 실제 실행했다.
공식 Node 24.22.1 배포의 SHA256을 확인하고 사용했다. 게임 실행 파일의 PE 구조/임포트를
읽었으나, 이를 게임 규칙 추출에 성공한 것으로 표현하지 않는다.

게임 PAK 44개는 사용자 정의 magic 0x6B2A56B8, version 12, 암호화된 인덱스를 사용한다.
REA의 일반 아카이브 분석은 이 형식을 지원하지 않았다.
[CUE4Parse](https://github.com/FabianFG/CUE4Parse)의 Torchlight 전용 구조와 대조해
인덱스 위치를 식별했다. 실행 파일의 제한된 정적 후보 검색은 235개 후보 중 인덱스
SHA1 검증을 통과한 키가 0개였다. **규칙 테이블 복호화/추출은 실패했다.**
게임 프로세스 입력, 메모리 패치, 계정 캐시, 네트워크 토큰을 사용하지 않았다.
게임 바이너리나 추출 자산을 공개 저장소에 넣지 않는다.

## 이번 학습 및 평가 설계

`gpu_chain_rl.py`는 종료 보상을 사용하는 Monte Carlo 가치 학습과 정책 개선을 2회 수행한다.
PPO나 트랜스포머가 아니다. CUDA에서 정규화 선형 잔차를 학습하고 기존 값에 0.5 비율로
적용한다. 내보낸 모델은 Rust CPU에서만 계산한다.

- 세대별 학습 50,000판: 일반 30,000 + 부화/성수/해부/만능약 각각 5,000.
- 세대별 독립 검증 5,000판. 총 학습 100,000판, 검증 10,000판.
- 입력 1,316개: 기존 656 + 종족/희귀도/도구/획득 시점 564 + 후속 연계 96.
- 첫 실험은 1,120,000 달성 여부, 두 번째는 그 상한까지의 연속 점수를 학습 보상으로 사용.
  두 실험 모두 초과 점수는 추가 보상 없음. 아래 실패/재설계 절에 결과를 분리 기록.
- 두 후보를 별도 512판/64 futures에서 선별. 최종 결과를 보고 후보를 바꾸지 않음.
- 고정 holdout 8,192판/256 futures. 기존 가중치 및 840k 목표 정책과 전체 정책을 비교.
  따라서 모델 가중치만의 인과 효과로 해석하지 않음.
- 특수 계열은 각각 별도의 256판/256 futures. 모두 2라운드 강제 진입이며 실제 빈도 추정 아님.
- 1.12M 성공률을 주 지표로, 840k/30만 미만/하위 10%/몬스터 수/탱크 수/CPU 시간을 함께 기록.
- 몬스터 수는 동률 시 우선순위이며, 성공률을 희생하는 고정 패널티를 추가하지 않음.
- 시행 전에 시드, 판수, 기준을 `plan.json`과 SHA256으로 고정. p값을 보며 판수를 연장하지 않음.
- 새 모델 자동 설치/배포 없음. 실험 결과, 규칙 불확실성, 속도를 함께 검토해야 함.

기존 실험의 JSON 264개에서 시드 항목 24,728개를 점검했다. 과거 최대 확인 시드는
107,000,023이고 `run02`의 학습/검증/선별/holdout은 10억 이상으로 분리했다.
각 폴더의 계획과 엔진/모델 SHA256을 남긴다. 잘못 입력한 연구 목표/시나리오를 기본값으로
조용히 바꾸는 CLI 동작도 거부하도록 수정했다. 기존 `gate`는 840k 전용임을 명시하며,
다른 목표 플래그를 주면 실패한다. 이번 평가는 별도의 대응 평가기를 사용한다.

한정된 탐색 정책으로 생성한 종료 결과를 학습하므로 최적 가치 함수의 정답 데이터는 아니다.
학습 오차 감소만으로 정책이 개선됐다고 선언하지 않고 독립 게임 평가 결과를 사용한다.

## 첫 목적함수의 실제 실패와 두 번째 실험

`qa/chain-rl/run01`의 두 후보는 각각 50,000판씩 학습을 마쳤고 CPU/GPU 대조도 통과했다.
하지만 별도 512판 선별에서 저점이 크게 나빠졌다.

| 정책 | 1.12M 이상 | 300k 미만 | 하위 10% |
|---|---:|---:|---:|
| 기존 | 99/512 | 7/512 | 569,859 |
| 1세대 이진 보상 | 236/512 | 132/512 | 57,989 |
| 2세대 이진 보상 | 244/512 | 139/512 | 63,042 |

목표에 못 미친 모든 결과를 같은 0 보상으로 취급하면, 목표 달성률을 올리면서 심한 실패를
늘리는 정책도 선호할 수 있다. 이 후보를 실제 오버레이에 적용하지 않았다. 시작된 기존
모델 holdout 작업은 완료 전에 중단했고 후보 holdout은 실행하지 않았다. 8,192판 검증을
완료했다고 주장하지 않으며, 선별 데이터를 본 뒤의 판단이므로 최종 검정 결과로 취급하지 않는다.

`run02`는 별도 시드를 사용하고, 목표까지의 점수를 그대로 보상하는 기존의 연속형 목적함수를
1.12M 상한으로 학습한다. 목표 미달 시에도 90만과 3만을 다르게 평가한다. 두 세대/10만 판
학습 구성은 같고, 기존 가중치의 목표만 변경한 대조군도 포함한다.
선별 전에 아래 규칙을 새 `plan.json`에 고정했다.

- 512판 선별에서 300k 미만 횟수가 기존 이하여야 한다.
- 하위 10% 점수가 기존 이상이어야 한다.
- CPU 완주 시간이 기존의 1.35배 이하여야 한다.
- 이를 만족하는 후보 중 1.12M 달성 횟수가 가장 많은 하나를 선정한다.
- 만족하는 후보가 없으면 채택하지 않는다. 이 선별 규칙은 통계적 비열등성 증명이 아니다.
- 통과 후보가 있을 때만 새 8,192판/256 futures 및 별도 특수 계열 평가를 수행한다.

완료된 최종 결과는 [별도 보고서](CHAIN-MODEL-RESULTS.md)에 기록했다. 앞선 실패를 숨기거나
결과가 좋은 판만 모아 성공률을 계산하지 않았다.

## 목표 변경과 가중치 효과를 분리한 추가 확증

첫 8,192판에서 기존 가중치/840k 목표와 후보/1.12M 목표의 차이는 +31.70%포인트였다.
그러나 같은 1.12M 목표의 별도 1,024판 진단은 570 -> 595회, 차이 +2.44%포인트,
95% 대응 bootstrap 구간 -0.98~5.76%포인트, exact p=.1748이었다.
따라서 큰 전체 정책 개선을 새 가중치의 성능 향상으로 단정하면 안 된다.

이 진단 표본을 결과에 따라 연장하지 않고, 새 시드 1,270,000,000부터 8,192개를 사용한다.
`chain_confirmation.py`가 동일한 목표 1,120,000, 동일한 포션/도구 리롤 3/1,
256 futures, CPU 8스레드로 기존 가중치와 고정 후보 g1을 비교한다. 추가 학습이나 재선별은 없다.
주 지표는 1.12M 달성률의 대응 차이, 양측 exact McNemar 유의수준 .05다.
계획 가정 q=.4/차이2%포인트의 검정력은 약81.2%이며 나머지 저점/수량/시간은 별도 진단한다.
모델을 자동 교체하지 않으며, 이 검정은 실제 규칙과 보상 모델의 정확성을 보증하지 않는다.

실행 전 계획 SHA256: `daf2cdd8866361d0b972c30350afc68aea22582f8861b64e3c562c355e19349d`.
출력: `qa/chain-rl/run03-confirm-v2`. 첫 시작은 가중치/결과 파일명의 충돌을 덮어쓰기 방지가
차단해 0판에서 멈췄다. 출력 이름을 분리한 새 폴더로 시작했으며 모델/시드/평가 조건은 동일하다.
최종 결과에 따라 판수를 바꾸거나 실패한 시드를 제외하지 않는다.

완료 결과: 동일 목표에서 기존 4,536/8,192, 후보 4,640/8,192로 차이는 +1.27%포인트,
95% 대응 bootstrap 구간 +0.04~+2.51, exact p=.04531이었다. 사전 주 검정은 통과했지만
30만 미만 감소는 불확실(p=.33286)했고, CPU 완주 경과시간은 +31.68%였다.
몬스터 수량은 -1.55%이나 실제 전투시간은 측정하지 않았다. 기본 가중치는 유지했다.
두 실험 합계 학습 200,000판/검증 20,000판이며, 완주한 최종·부가 평가의 물리적 실행은
36,864게임이다. 재사용한 1,024개 후보 결과를 중복 집계하지 않았고, 이 총 실행 수를
하나의 검정에 사용한 독립 표본 수로 해석하지 않는다.

## 재현

개발용 Python 환경에 `vorax/scripts/requirements-finetune.txt`를 설치하고 CUDA를 준비한다.
실제 실험은 RTX 4060 Laptop, CuPy 14.2.0, SciPy 1.16.3을 사용했다. 배포 앱에는 이 환경을 넣지 않는다.
Rust release CLI를 빌드한 뒤 저장된 계획과 같은 설정으로 실행한다. 기존 결과 폴더를 덮어쓰지 않는다.

```powershell
python vorax/scripts/audit_sample_size.py --out qa/research/sample-size-reproduced.json
python vorax/scripts/gpu_chain_rl.py fit --run qa/chain-rl/reproduce --engine vorax/target/release/vorax.exe --threads 8 --objective target --seed-offset 1000000000
python vorax/scripts/gpu_chain_rl.py evaluate --run qa/chain-rl/reproduce --engine vorax/target/release/vorax.exe --threads 8 --objective target --seed-offset 1000000000
python vorax/scripts/chain_secondary_evaluate.py --run qa/chain-rl/reproduce --engine vorax/target/release/vorax.exe
python vorax/scripts/chain_confirmation.py --source qa/chain-rl/reproduce --run qa/chain-rl/reproduce-confirm --engine vorax/target/release/vorax.exe
```

위 시드는 공개된 실험의 재현 전용이며 새로운 후보를 확증하는 독립 검증 시드로 재사용하지 않는다.
CPU/컴파일러/라이브러리가 달라지면 수치/시간 차이가 생길 수 있다. 원 실험의 실행 파일 해시,
모델 해시, 학습 데이터 메타데이터와 최종 시드별 결과는 최종 결과 파일에 함께 기록한다.
