# 1.0.9 목표 점수와 낮은 점수 개선 검증

## 추천 목적

1.0.8의 상한 없는 평균 점수 대신, 최종 활성의 `min(점수, 840000)` 평균을 최대화한다. 이는 `max(840000 - 점수, 0)`의 평균을 최소화하는 것과 같다. 목표를 넘은 일부 대박이 낮은 결과를 보상하는 정도를 제한한다. 최저 점수를 보장하거나 달성 확률만을 최대화하는 목적 함수는 아니다.

이 값이 정확히 같으면 84만 달성 비율, 최종 몬스터 총수, 남은 탱크 수를 차례로 비교한다. 개체 수가 적다는 이유로 더 낮은 점수 기대값이나 달성률을 선택하지 않는다. 몬스터 종류, 체력, 플레이어 피해량에 따른 실제 전투 시간은 측정하지 않았다.

화면 추천과 전체 게임 평가가 같은 비교 함수를 사용한다. 현재 규칙에서는 시뮬레이션 결과를 포션 상자 우선, 효과 없는 카드 회피, 즉시 점수 기반 리롤 규칙으로 다시 덮어쓰지 않는다. MIT 원본 회귀 자료는 별도 기준 규칙으로 그대로 재생한다.

## 84만의 의미

[솔버 작성자의 공개 설명](https://www.reddit.com/r/TorchlightInfinite/comments/1xeu4lt/vorax_solver_8x_faster_and_25_better_suggesitons/)은 84만과 마지막 세 장의 추가 활성 카드를 함께 무지개 목표로 설명한다. [이용자의 보상 비교](https://www.reddit.com/r/TorchlightInfinite/comments/1r7q047/vorax_surgery_max/)에는 약 110만 이후 보상이 더 늘지 않는다는 보고가 있다. 공식 수치표로 확인한 정확한 상한이나 모든 플랜 조합의 보장은 아니다. UI는 무지개 확정률 대신 `84만 달성 예상`으로 표시한다. 11~13라운드 플랜과 전투 위험은 사용자가 판단한다.

## 검증 범위

실전 두 판에서 발견한 효과와 상태 변환 수정은 [실전 조사](BLOODLUST-20261101.md)에 기록했다. 원본 화면과 실제 선택 기록이 없어 원인을 구분하지 못한 종족 전이 1개는 여전히 미해결이다. 모든 실전 오류를 없앴다고 주장하지 않는다.

학습과 추천 정책 평가는 서로 다른 시드를 사용한다. 도구 리롤은 앞서 기록된 두 판과 같은 1회, 포션 리롤은 3회로 맞춘다. 기본 UI는 선택지당 1,024회이지만 전체 판 비교는 계산량을 제한하기 위해 양쪽 모두 256회를 사용한다. 확률표와 규칙이 실제 게임과 다르면 평가 결과도 달라진다. 실전 완주나 수익 검증으로 해석하지 않는다.

## 실행 검증

- Rust 전체 release workspace: 81 passed, 0 failed, 0 ignored. 한국어 OCR, 화면 상태와 도구 복구, 리롤, 상자, 호버 위치, 고정 원본 parity 및 실전 전이 포함.
- .NET Release: 141 passed, 0 failed, 0 skipped.
- WPF 독립 실행형 1.0.9 publish와 두 탭 렌더 성공.
- 기존 Rust dead-code 경고 6개와 .NET 테스트 CA2014 경고 1개는 유지한다.

## 점수 분포

512개 시드 `17000000..17000511`, 선택지당 256회, 포션/도구 리롤 3/1. 두 정책에 같은 수정된 규칙과 같은 기존 학습 가중치를 사용했다. 따라서 이 표는 1.0.8 실행 파일과의 전체 변경 비교가 아니라 추천 목적의 비교다. [시드별 원자료](benchmarks/target-1.0.9.json)에 조건과 해시를 포함했다.

| 항목 | 상한 없는 평균 목표 | 배포할 84만 목표 |
|---|---:|---:|
| 84만 달성 | 367/512 (71.7%) | 380/512 (74.2%) |
| 하위 10% 경계 | 557,957 | 572,132 |
| 하위 10% 평균 | 411,969 | 421,529 |
| 30만 미만 | 8/512 | 9/512 |
| 관측 최솟값 | 63,908 | 125,268 |
| 84만까지 계산한 평균 | 770,227 | 779,195 |
| 상한 없는 평균 | 1,464,513 | 984,843 |
| 최종 몬스터 총수 평균 | 2,298.4 | 1,987.7 |
| 남은 탱크 수 평균 | 3.58 | 3.96 |

달성률 차이의 paired bootstrap 95% 구간은 -2.15~+7.23%p, 84만 상한 평균 차이는 -4,804~+23,237이다. 이 표본에서 일부 지표가 올랐지만 통계적으로 확실한 개선으로 판단할 수 없다. 30만 미만은 오히려 1회 늘었다. 최솟값이나 몬스터 총수의 변화도 최저 점수 보장이나 전투 시간 단축률로 해석하지 않는다. 전투량보다 점수 목적이 우선이므로 탱크 수가 항상 감소하지도 않는다.

## 채택하지 않은 후보

- 도구 리롤 1회 조건으로 20만 판 학습/2만 판 회귀 검증: 동일 512개 개발 시드에서 기존 가중치 394회, 후보 380회가 84만 달성. `vorax gate` 실패.
- 100만 판 학습/10만 판 회귀 검증: 동일 256개 개발 시드에서 기존 202회, 후보 198회. `vorax gate` 실패. 초기 중단된 순차 검사는 별도 결과로 합산하지 않았다.
- 목표 부족분의 선형 손실과 제곱 손실을 같은 비중으로 계산하는 후보도 시험했다. 기존 정책 비교의 앞 256개 개발 시드에서 84만 달성 193 -> 192, 하위 10% 591,948 -> 584,201, 30만 미만 3 -> 4로 악화되어 제외했다. 이 추가 시도는 독립 검증 표본이 아니며 채택 근거로 사용하지 않았다.

재학습은 기존 정책 아래 가중치만 바꾼 개발 검사다. 새 가중치가 더 좋다는 근거가 없어 기존 `boardValue.json`을 그대로 유지했다. 사용자에게 적용하는 개선은 게임 규칙/상태 수정과 추천 목적의 변경이며, 새 학습 모델을 탑재했다고 주장하지 않는다.

## 계산량

몬스터 수는 이미 시뮬레이션한 최종 상태의 여섯 탱크에서 합산한다. 이를 위해 미래를 다시 시뮬레이션하거나 탐색 횟수를 늘리지 않는다. 기존 후보 중복 조회 제거와 상태 복사 감소를 유지하며, 병렬 결과는 최대 1,024개씩 합산한다. 몬스터 수 필드가 추가된 임시 합산 버퍼는 최대 32KiB다. 캡처/OCR과 게임 프레임 영향은 계산 시간과 별개다.

## 설치와 ZIP

두 기존 설치 폴더를 1.0.9.0으로 갱신했고 설치 시 설정 파일 4개의 SHA-256이 유지됐다. 중복 실행을 종료하고 기존 데스크톱 설치본 하나를 실행했다. Computer Use로 실제 1.0.9 설정 창, 자동 감지 대기, 새 설명 문구를 확인했다. 게임이 꺼져 있어 실행 중인 블러드 러스트 엔진은 없었다.

새 한글/공백 경로에 ZIP을 해제한 뒤 1,006개 payload 파일의 크기와 SHA-256을 전수 대조했다. WPF 두 탭 렌더, 네이티브 저장 화면 미리보기, 5회 화면 처리 검사가 모두 종료 코드 0이었다. 설치된 데스크톱 복사본도 같은 1,006개 파일을 검증했다. 별도 Windows PC에서의 검사는 아니다.

- ZIP: `TorchlightHelper-KO-1.0.9-win-x64.zip`, 109,057,976 bytes.
- SHA-256: `4ba34ff9df3ac6c8038fd1beb765320a7e29f5c649a1baa3ebd677eaf9c5446f`.
- 네이티브 SHA-256: `c88fe2b18f5e6e67d7862ef401792cb02973eaef013190859093059cb987ef4e`.
- ZIP은 매니페스트 포함 1,007개 항목이며 사용자 설정/로그/진단 이미지/디버그 심벌과 개발 PC 경로를 제외했다.

같은 저장 화면, 선택지당 1,024회, 8스레드의 첫 처리는 1,005.7ms였다. OCR 초기화 등을 포함한 읽기 871.7ms, 추천 계산 133ms이며 캡처와 애니메이션 대기는 포함하지 않는다. 같은 화면의 후속 처리는 캐시를 사용한다. [5회 측정 원자료](benchmarks/frame-time-1.0.9.json)를 함께 공개한다. 한 화면의 측정이므로 보편적인 지연 상한이나 이전 버전 대비 속도 개선으로 주장하지 않는다.
